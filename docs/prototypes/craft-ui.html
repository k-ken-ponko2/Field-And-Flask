クラフトUI設計案 — 土器と石器

◐ theme

多数の実工程（採取・精製・成形・接合・熱処理…）を、そのまま個別ミニゲーム化すると破綻する。 Potion Craft の手触り（空間的・直接操作・目標領域）を保ちつつ、工程の性質で 数種類のUI原型に畳む。土器＝「化学＋熱処理」系、石器＝「賦形」系で、必要な原型がはっきり分かれる。

0UIの原型に畳む

原型担当する工程操作の核状態
A 状態空間マップ精製・製錬・合成・焼成・熱処理・調合温度×濃度 等の平面を目標領域へ navigate実装済
B 工程チェーン材料前処理（粉砕→篩分け→乾燥→造粒）素材の属性が左→右へ流れる未
C 直接賦形鋳造・鍛造・プレス・剥離・研削形そのものを直接いじる（削る/叩く）未
D 接合・組立溶接・ろう付け・締結・接着部品を繋ぐ未

「化学」系はほぼ A に落ちる（＝反応マップで実装済）。「形」系は C で、新しい操作が要る。土器と石器はこの差を示す。

状態マップ(ヤマ場)

背骨は工程チェーン(B)。属性（可塑性・水分・粒度）がノードを流れる。ヤマ場の焼成だけ状態マップ(A)を入れ子にする＝反応マップのエンジンを軸だけ差し替えて流用できる。

時間 →焼成マップ：温度 × 時間

焼成マップ (A) の狙い

  • 素焼き＝目標領域（十分な温度×時間）
  • ひび割れ＝暴走域：生乾きを急加熱すると突入（＝反応マップの hazard と同型）
  • 熔け・過焼＝高温すぎ
  • 低温・短時間は生焼けで未達

→ 乾燥→予熱→本焼と時間をかけて素焼き領域へ。収率＝経路効率は反応マップと同じ。

こちらは状態マップではない。石核を直接いじって形を作る賦形(C)が核。Potion Craft の「直接操作」を“空間ナビ”ではなく“造形”に振る。

石核をクリックで打点選択剥離(ナッピング)UI

剥離UI (C) の狙い

  • 石核を表示。薄く目標シルエット（鏃/ナイフ/斧）を重ねる
  • 打点と打撃角度を選ぶ→フレークが剥がれ形が変わる（除去加工＝subtractive）
  • 良い角度＝大きく整形／悪い角度＝破断・失敗（素材ロス＝hazard 相当）
  • 材料同定の質が成功率・剥がれ方に効く（黒曜石は綺麗に、砂岩は砕けやすい）

破損リスク

→ 稜線に沿って浅く打つと長いフレークが取れ、目標形に近づく。

?相談したい論点

Q1 — 原型の数
クラフトUIの「型」をいくつに絞る？
全部で A/B/C/D の4種？ まずは A(状態マップ)＋C(賦形) の2本に絞って、B(前処理)はチェーン表示だけの簡易版で始める、が現実的。
Q2 — 賦形(C)を本当に作るか
石器・鍛造に“造形UI”を入れる？ それとも簡略化してA/Bに寄せる？
造形UIは手触りが濃いが実装コスト大。割り切って「打撃を数回選ぶ→結果判定」の軽い賦形に留める案もある。
Q3 — 入れ子構造
焼成のように「チェーン(B)の1ノードがマップ(A)」の入れ子でよい？
これを許すと、工程チェーンを背骨に、要所だけ濃いミニゲームを差し込む統一設計にできる。

※ 焼成マップ(A)は既存の reaction_map/reaction_sim エンジンを軸ラベル差し替えで流用できる（実装コスト小）。 剥離UI(C)は新規の造形インタラクションが必要（コスト中〜大）。上のモックアップは方向性を示す試作で、数値・形は仮。
