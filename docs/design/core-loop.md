# コアループの駆動部：レシピ逆算と実験ノート

> 設計書 §2（コアループ）と §7（記録と委任）を実装レベルに落としたもの。
> 反応マップ（`docs/design/reaction-map.md`）が「1回の調合」なら、こちらは
> 「何を作るべきか」と「一度作ったものをどう資産にするか」を扱う。

---

## ② 目標の出題ロジック（願い → 必要物質の逆算）

コアループ①②「願いが提示される → 何が要るかを推理する」の“システム側”。
プレイヤーの推理を奪わず、**依存関係の表現と逆算**（クエストログ・ヒント・達成判定用）を担う。

### データ

`Recipe`（`data/recipes/*.tres`）＝「ある物を作るのに何が要るか」の1ノード。

| フィールド | 意味 |
|---|---|
| `product_id` | 生成物 |
| `inputs` | 必要な入力（素材・中間生成物）の id |
| `map_id` | 反応マップ経由なら指定（&"" なら単純加工） |
| `tech_id` | 必要な設備・技術（§2 の制約解除に対応） |

### ソルバー（`RecipeBook.resolve`）

願い `goal_id` と所持品 `owned` を渡すと、後ろ向きにたどって計画を返す：

```
{
  ok:          既知レシピで葉（原料）まで辿れたか（循環が無いか）
  steps:       作るべき工程順（依存を先に、goal を最後に＝トポロジカル順）
  raw_needed:  レシピが無く採取が必要な原料（所持分は除く）
  tech_needed: 必要な設備・技術
}
```

**例（病人を治したい）**：`cure ← sulfa_drug ← dilute_sulfuric_acid ← vitriol(採取)`

- `steps = [dilute_sulfuric_acid, sulfa_drug, cure]`
- `raw_needed = [vitriol]`（＝火山地帯へ採取遠征）
- `tech_needed = [glass_flask, synthesis_bench]`（＝先に作るべき設備）

所持品で枝刈りされるので、`owned=[dilute_sulfuric_acid]` なら工程は `[sulfa_drug, cure]` だけになり、原料採取も設備要求も消える。循環依存は `ok=false` で検出する。

## ③ 実験ノート（経路の保存・再生・委任量産）

設計書 §7「必須」。**初回だけが推理ゲーム、二回目以降は資産**を成立させる。

### 記録

`ReactionSim` は操作を逐次 `operations` に記録する（加熱・加水・蒸留・酸/塩基・素材投入）。
`sim.to_note()` で、操作列＋開始点＋到達物質＋収率を `ReactionNote`（Resource＝`.tres` 保存可）に固める。

### 再生（決定的な再現）

`note.replay(map, materials)` は同じ開始点から操作列を流し、**同じ座標・pH・収率・到達物質**を再現する。
`materials` は `id → MaterialDef` の辞書（素材投入の解決に使う）。これが「自動でなぞる」の下地。

### 委任量産（`note.produce`）

UI を起動せず、入力素材から生産結果を計算する：

```
量   = 入力量 × 記録した収率     （経路の効率ぶんだけ目減り）
純度 = base_purity × 入力純度    （不純な素材からは不純な生成物）
```

これで仲間への委任・量産が純粋ロジックで回り、`Substance` / `Purity` とつながる。

## つながり

```
願い ──resolve──▶ 必要物質の工程順＋原料＋設備
                     │
              （原料を採取・遠征）
                     │
     反応マップで経路を引く（初回＝推理）
                     │
                to_note ──▶ 実験ノート(.tres)
                     │              │
                  replay        produce
              （自動なぞり）   （委任量産）
```

すべて `core/`（副作用なし）に載っており、`core/__tests__/run_tests.gd` でヘッドレス検証される。
