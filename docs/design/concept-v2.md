# Field & Flask（仮題）ゲームコンセプト設計書 v2

> 採取・精製・創造に特化した科学クラフトゲーム
> ステータス: コンセプト確定 / 想定規模: 数十時間 / エンジン: Godot 4.7

---

## 0. 一行要約

**石器時代同然の世界で、素材を探して集め、化学の力で文明の道具を一つずつ取り戻していくゲーム。**

- マップ・採取の手触り: Stardew Valley
- クラフト・調合の手触り: Potion Craft
- 技術の積み上げ方: 目標から逆算する技術ツリー

---

## 1. 設計の4軸

| 軸 | 担当する参照元 |
|---|---|
| 素材集めの探索・遠征 | Stardew Valley のマップとエリア解放 |
| 時間・資源のやりくり | Stardew Valley のカレンダーと季節 |
| レシピを推理して発見する | Potion Craft の錬金マップ |
| 化学反応の再現・精製工程 | Potion Craft の直接操作 |

**原則: 4軸を独立したシステムとして並べない。一本の因果で数珠つなぎにする。**

---

## 2. コアループ

```
① 誰かの「願い」が提示される（ラーメンが食べたい / 病人を治したい）
        ↓  ← レシピ推理
② 何が必要かを推理する（薬 → サルファ剤 → 硫酸が要る）
        ↓  ← 探索・遠征
③ どこにあるかを特定し、遠征を計画する（硫黄 = 火山地帯、片道3日）
        ↓  ← 時間・資源のやりくり
④ 採取して持ち帰る（容器・保存・季節の制約）
        ↓  ← 化学反応・精製
⑤ 精製し、反応させる（純度が足りなければ用途が限られる）
        ↓
⑥ 完成した道具が「行動の制約」を解除する
        ↓
   より遠い産地・より高い温度・より難しい願いへ → ①に戻る
```

### 最重要ポイント: ⑥ の制約解除

**作った道具が次の採取を可能にする**一方通行の階段構造。
これを守れば、数十時間が「水増し」ではなく「積み上げ」になる。

| 獲得する技術 | 解除される制約 |
|---|---|
| 土器 | 液体を運べる・煮沸できる |
| 炭焼き窯 | 高温が出せる → 金属精錬が解禁 |
| ふいご | さらに高温 → 鉄・ガラス |
| 荷車・気球 | 遠方の産地へ到達可能 |
| 密閉容器・保冷 | 揮発性・腐敗性の素材を持ち帰れる |

## 3. 反応マップ（本作の核心）

Potion Craft の錬金マップを、**実在の化学の状態空間**に置き換える。

### 3.1 構造

- **2軸の連続平面**（第一候補: 温度 × 濃度）
- 目標物質は平面上の**領域**として存在する（点ではない）
- 現在地はマーカーとして表示され、操作によって移動する

| 操作 | 移動 |
|---|---|
| 加熱 | 上へ |
| 加水 | 左へ |
| 蒸留 | 右へ（収率は落ちる） |
| 素材投入 | その素材固有の方向へ跳躍 |

### 3.2 領域の種類

- **目標領域**: 希硫酸、濃硫酸など。到達すれば物質を得る
- **暴走域**: 爆発・有毒ガス発生。侵入するとペナルティ
- **未踏領域**: 霧で隠されている。設備の性能が霧の晴れる範囲を決める

### 3.3 なぜこの方式が優れているか

- **物理的な直感で推理できる**。「加熱しすぎると暴走しそうだから先に薄めよう」という判断が化学の知識ゼロでも成立する
- **知識がある人は最短ルートを一発で引ける**。難易度の自然な二層構造が生まれる
- **経路の効率が収率になる**。遠回りすると同じ物質でも収率が落ちる → 上手い経路を探す動機
- **素材の跳躍方向を覚えることが、そのまま知識の蓄積になる**

### 3.4 マップは分野ごとに分割する

1枚のマップを踏破し尽くすと終わってしまう（Potion Craft の構造的弱点）。

- 酸・塩基系マップ
- 冶金系マップ
- 有機系マップ
- 電気化学系マップ

新しい設備を作ると新しいマップが解放される。**技術ツリーの解除と一対一で対応**させる。

---

## 4. 純度という第二のパラメータ

- 同じ硫酸でも純度60%と98%では使える用途が違う
- 蒸留・ろ過・再結晶・焼成といった工程が意味を持つ
- **一度訪れた産地に再訪する理由**が生まれ、後半のコンテンツ枯渇を防ぐ

---

## 5. Stardew Valley から取るもの／取らないもの

### 取るもの

- **拠点＋放射状のエリア**構造（研究所を中心に、森・洞窟・火山・海岸）
- **季節と天候による採取物の変化**（硝石の洞窟は雨季に水没、製塩は晴天が必要）
- **道具のティアが採取範囲を決める**構造
- **鉱山型の深度構造**（深く潜るほど希少な鉱物）
- **仲間との関係が委任の解放につながる**

### 取らないもの

- **農業と作物の栽培サイクル** — 軸が5本になって焦点がぼける
- **恋愛・結婚** — 仲間は「専門技能を持つ協力者」に振り切る
- **スタミナによる1日の強制終了** — 後述のテンポ問題の元凶

---

## 6. 最大の危険: テンポの衝突

Stardew Valley は1日を消費してまったり進むゲーム、Potion Craft は1回の調合に集中するゲーム。
素朴に接続すると**「1日1回しか実験できない」**という最悪の設計になり、推理が全く進まない。

### 解決策: 実験規模と工業規模の分離

- **実験室内では時間が進まない（あるいはほぼ進まない）**。微量素材で何度でも経路を試せる
- **時間を消費するのは「遠征」と「本番生産」だけ**
- 素材が尽きたら遠征に出る、というリズムになる

これにより「採取＝時間とリスクのゾーン」「実験＝安全な思考のゾーン」と役割が分離し、
両方のゲームの気持ちよさが壊れずに同居する。

---

## 7. その他の対策

### 実験ノートによる記録と委任

- 一度成功させた反応（経路）はノートに保存され、次回から自動でなぞれる
- 仲間に委任して量産できる
- **初回だけが推理ゲーム、二回目以降は作業ではなく資産**になる
- 「分業で文明を作る」テーマ的にも正しく、数十時間を支えるには必須

## 8. 技術選定

### エンジン: Godot 4.7（確定）

| 項目 | 内容 |
|---|---|
| ライセンス | MIT、完全無料・ロイヤリティなし |
| 選定理由 | UIノードが標準で強い / Resource によるデータ駆動 / 反復速度が速い / 運営体制のリスクが低い |
| 懸念 | Steam連携はGodotSteam（サードパーティ）経由 / アセット資産はUnityに劣る |

### 実装メモ

| 要素 | 実装方針 |
|---|---|
| 反応マップ | `Node2D` + カスタム描画。霧はシェーダで動的マスク。領域判定は座標の内外判定 |
| 素材・反応領域の定義 | `Resource`（`.tres`）でデータ駆動。**領域を目視配置できるツールスクリプトを早期に作る** |
| マップ・採取 | `TileMapLayer`。斜め見下ろしならYソート必須 |
| カレンダー・季節 | 純粋ロジック。エンジン非依存の層に置く |
| Steam | GodotSteam で実績・クラウドセーブ |

### 設計原則: ロジックの分離

```
core/          ← 副作用なし。素材・反応・純度計算・テストのみ
  materials/
  reactions/
  calendar/
  __tests__/
presentation/  ← エンジン依存。描画とUIのみ
```

「純度72%の硫酸で反応Xは成立するか」をUIを起動せず検証できることが、
数十時間規模のバランス調整では決定的な差になる。

### Steam リリース時の実務

- Steam Direct 登録料が作品ごとに必要
- Steam Deck 検証は早めに通す（発見性に有利）
- Workshop対応を視野に入れるならデータ駆動設計が前提になる

## 9. 仮タイトル

### 採用（仮）: **Field & Flask**

日本語表記: フィールド＆フラスコ

**選定理由**

- **ゲームの二つの半身をそのまま名指ししている**（野外での採取 / 実験室での調合）
- 頭韻が効いていて口に出しやすく、記憶に残る
- Steam検索での競合が少なく、識別性が高い
- 牧歌的な響き（Field）と科学的な響き（Flask）の同居が、本作のトーンと一致する

### 次点候補

| 候補 | 方向性 |
|---|---|
| Alembic | 蒸留器の名。神秘性と科学性の同居 |
| Root & Reagent | Field & Flask と同系統。より薬学寄り |
| Rekindle | 文明の再点火。テーマ寄りだがジャンルが伝わらない |
| 灰から始める化学 | 日本語圏向け。直球だが長い |

### 確定前に確認すること

- Steam ストアでの同名タイトルの有無
- 商標の抵触
- ドメインとSNSハンドルの空き状況

## 10. 次に決めるべきこと（決定済み）

> 詳細と数値モデルは `docs/design/reaction-map.md` を参照。

1. **反応マップの軸** → **温度 × 濃度**（2D）に確定。
   加えて **pH を第3の要素**として、移動軸ではなく **連続値の等高線オーバーレイ**で表現する。
   pH は「直接いじる値」ではなく組成（酸/塩基の量）と濃度から決まる“結果”とし、**中和**を独立レバーにする。
   （pH×酸化還元は後半の「電気化学系マップ」に回す）
2. **経路の「なぞり方」** → **連続タクタイル（直接操作）に更新**（旧：離散工程）。
   クラフトの全処理をタクタイル操作で実装する方針に伴い、反応マップの入力もボタン積みから
   **直接操作**へ。ただし**下のシミュレーション（温度×濃度・pH・収率・領域）は不変**で、変わるのは入力層のみ。
   詳細は `docs/design/tactile-crafting.md`。
3. **暴走・失敗のペナルティ** → **素材ロス＋設備耐久**に確定。
   縁をかすめると収率減、突入でバッチ全損、高温の深部ではさらに設備ダメージ。
   **キャラ負傷は不採用**（§6 のテンポ原則を自ら壊さない）。

### 追加で確定した方針

- **クラフトの全処理をタクタイル操作で実装する**（設計原則）。詳細 `docs/design/tactile-crafting.md`。
  - タクタイル＝「直接操作という入力」であり、時間/経済とは独立。実験レイヤは時間ゼロ・やり直し自由のまま（§6）。
  - 50種の個別ミニゲームにせず、**7つの原型ジェスチャ**（なぞる/あおぐ/叩く/こねる/掴んで落とす/回す/押す引く）に畳む。
  - 量産は**実験ノートの記録→再生で自動化**（タクタイルは*発見時*のみ、*量産*は自動）。アシスト/オートも用意。
- **熱源の4段階＝温度軸の到達天井**（制約解除⑥の温度版）。詳細 `docs/design/heat-tiers.md`。
